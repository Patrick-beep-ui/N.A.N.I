# Estándar de frontend y diseño

Estado: plantilla inicial. Aún no hay suficientes ejemplos aprobados para afirmar un estilo visual personal.

## Principios provisionales

- Diseñar primero la jerarquía de información y luego la decoración.
- Mantener espaciado, tipografía, color y estados mediante tokens reutilizables.
- Construir componentes con responsabilidades y variantes claras.
- Incluir estados de carga, vacío, error, éxito y deshabilitado.
- Priorizar accesibilidad: estructura semántica, teclado, foco visible, contraste y etiquetas.
- Adaptar la interfaz a pantallas pequeñas sin ocultar acciones esenciales.
- Evitar animación o elementos visuales que no comuniquen estado, prioridad o relación.

## Revisión de una interfaz

- ¿La acción principal se entiende sin explicación?
- ¿La jerarquía visual coincide con la importancia del contenido?
- ¿Espaciados y alineaciones siguen un sistema reconocible?
- ¿Los componentes iguales se comportan igual?
- ¿Existen estados para carga, error, vacío y confirmación?
- ¿Puede usarse con teclado y lector de pantalla?
- ¿La densidad visual es adecuada al tipo de producto?

## Evidencia necesaria

Agregar a `examples/`:

- Una landing page aprobada.
- Un dashboard aprobado.
- Un flujo o formulario aprobado.
- Correcciones de diseño con explicación del motivo.

Hasta contar con esa evidencia, cualquier afirmación sobre el gusto visual del usuario debe marcarse como inferida o propuesta.
